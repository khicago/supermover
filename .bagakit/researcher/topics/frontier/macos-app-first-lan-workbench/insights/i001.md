# Make contracts precede polish

## Insight

The app-first workbench should be planned as an evidence/control-plane contract feature before it is planned as visual polish: profile bootstrap, command coverage, process supervision, events, artifact readers, and validation gates must come before complete transfer screens.

## Why It Matters

This feature is meant to support a real cross-device migration. A polished UI
without command coverage, event truth, and platform readiness would make the
system feel safer than it is.

## Borrow
- Keep the selected high-craft native UI direction, but drive it from explicit
  role, command, event, and artifact contracts.

## Avoid
- Avoid adding transfer screens around text scraping, single-process assumptions,
  or unsupported root comparison labels.

## Bagakit Implication
- The revised feature plan should be the implementation gate before any further
  app expansion.
